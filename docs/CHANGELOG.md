# سجل التغييرات — Global Enterprise Pharmacy ERP

## Iteration 1 — Full Modular Enterprise Foundation
- إضافة نظام ألوان Enterprise Dark وRTL ومكونات الأرصدة والتنبيهات والتحقق الإداري.
- إضافة نماذج الأدوية ذات 19 نقطة سريرية وتجارية ونماذج الأطراف والسندات والفواتير والتبويبات.
- إنشاء مخطط SQLite شاملاً للنواة والفروع والمستخدمين والإعدادات والتسلسل والموسوعة والدفتر والقيد المزدوج والصناديق والسندات والمبيعات.
- تفعيل مفاتيح SQLite الخارجية وWAL وNORMAL وbusy_timeout وMEMORY.
- إضافة بذر أولي للفرع والحسابات والصناديق والمحافظ والأطراف وستة أصناف دوائية تجريبية.
- إضافة محرك ترحيل معاملات البيع والسندات مع قيد مزدوج متوازن وتحديث دفتر الأطراف والصناديق.
- إضافة مزودي الجلسة وبيانات ERP والكاشير والموسوعة والتبويبات السريعة.
- إضافة لوحة مؤشرات، كاشير متعدد التبويبات، موسوعة دوائية، وشاشة الأطراف والسندات.
- إضافة اختبارات وحدات لتحويل وحدات البيع واكتمال بيانات الدواء.

## تنبيهات واعتمادات
- بيانات seed السريرية توضيحية مرجعية أولية، ويجب مراجعتها مع النشرات المحلية ومراجع صيدلانية معتمدة قبل استخدامها في قرار علاجي.
- كلمة مرور المالك ورمز المدير بيانات تأسيسية للاختبار ويجب تغييرهما قبل التشغيل الفعلي. تُخزّن كلمة المرور ورموز المدير باستخدام PBKDF2-HMAC-SHA256 مع Salt عشوائي؛ يجب تغيير بيانات التأسيس قبل الإنتاج، وإضافة سياسات تدوير الأسرار وتحديد محاولات الدخول.
- القيد المزدوج يفرض التوازن على مستوى خدمة الترحيل، ويجب إضافة اختبارات تكامل وفحوص سلامة دورية للقيود.
- عدد ملفات الدورة 15 في التسمية الأصلية، لكن البند 15 يتضمن ملف الشاشة وملف main.dart؛ لذلك يحتوي التسليم على 16 ملف Dart رئيسياً، إضافة إلى ملفات المشروع والاختبارات والتوثيق.


## استكمالات هندسية بعد البناء الأولي
- استكمال محرر الدواء ليشمل حقول النقاط السريرية والتجارية الـ19 مع حالة مراجعة صيدلانية للبيانات غير المتحققة.
- إدخال المواد الفعالة الثمانية اللازمة للأصناف الستة، بما فيها مكونات أوجمنتين وبانادول إكسترا.
- إضافة 35 إعداداً، ودليل حسابات موسع، وحركات افتتاحية للأطراف الأربعة.
- إضافة فحص الحد الائتماني، ترقيم تسلسلي للمستندات، اعتماد المدير برمز مخزن كتجزئة، ودعم الدفع المختلط.
- توسيع لوحة التحكم لتشمل آخر الفواتير والسندات وقائمة الأصناف منخفضة المخزون.
- إضافة اختبارات قاعدة البيانات ومهام CI لبناء Android APK وWindows Desktop.
- ملفات منصات Flutter تُولّد عبر `flutter create --platforms=android,windows .` عند تهيئة نسخة العمل.

- إضافة تحقق PBKDF2-HMAC-SHA256 مملح لكلمات المرور ورموز المدير، واختبارات للتحقق من التجزئة.
- تقييد استعلامات الموسوعة والأطراف والمؤشرات بالفرع النشط، وعزل حالة المريض لكل تبويب كاشير.
- إضافة حساب بنكي تجريبي، والتحقق من توافق وسيلة الدفع مع نوع حساب الصندوق، ودعم التسوية غير النقدية مع قيد متوازن.
- إضافة قيود محاسبية افتتاحية متوازنة للأطراف الجديدة وحركات الأطراف المزروعة.
- إصلاح قوس إغلاق مفقود في تخطيط قائمة موسوعة الأدوية تسبب في فشل `dart format` ضمن CI.
- معالجة القيم nullable لأعداد التعبئة قبل حساب أسعار الشريط والحبة.
- ضبط النوع الصريح لسجلات دفعات نقطة البيع لمنع استنتاج List<dynamic>.
- إعادة بناء قوائم موسوعة الأدوية بتراكيب Widget واضحة، وإصلاح استخدام BuildContext بعد الحفظ غير المتزامن.
- إضافة اختبار smoke بسيط باسم التطبيق الفعلي لمنع اختبار MyApp الافتراضي الذي ينشئه Flutter CI.- إحكام إغلاق إجراء حفظ محرر الدواء واستخدام مزود البيانات الملتقط قبل العملية غير المتزامنة، مع التحقق من mounted قبل تحديث الواجهة.
- إزالة استيراد غير مستخدم من شاشة الأطراف والسندات لتصفير تحذير التحليل المرتبط به.

- إصلاح أخطاء تحليل Dart الفعلية في بيانات الأرصدة الافتتاحية، وتعريف نسبة اكتمال الدواء، ومعالجة قيم وحدات العبوة nullable في حسابات البيع والترحيل.
- الإبقاء على `flutter analyze` كخطوة حاجزة وعدم تجاوز فشل التحليل؛ لم تُضف `continue-on-error` ولم تُخفَ أخطاء التحليل.

- إصلاح آخر استخدام nullable لـ `unitsPerPack` في تكلفة بند فاتورة البيع؛ توحيد الحساب على `effectiveUnitsPerPack` لتفادي تمرير `int?` إلى عملية حسابية تتطلب `num` غير nullable.

- ضبط فحص CI في Android وWindows باستخدام `flutter analyze --no-fatal-infos`؛ لأن Flutter يجعل ملاحظات info قاتلة افتراضياً. تظل أخطاء التحليل والتحذيرات قاتلة، ولا يُستخدم `continue-on-error` ولا يتم تجاوز فشل البناء أو الاختبارات.


## حزم التنزيل الموحدة — 2026-11-05
- توحيد مخرجات CI إلى Artifact واحد فقط للأندرويد باسم `pharmacy-android`، ويحتوي ملف ZIP واحداً باسم `pharmacy-android.zip` بداخله ملف APK.
- توحيد مخرجات CI إلى Artifact واحد فقط لويندوز باسم `pharmacy-windows`، ويحتوي ملف ZIP واحداً باسم `pharmacy-windows.zip` بداخله جميع ملفات مجلد Release اللازمة لتشغيل التطبيق.
- لا تُرفع ملفات APK أو ملفات Windows كـ Artifacts منفصلة؛ لكل منصة حزمة ZIP واحدة فقط.
- التغيير خاص بآلية التغليف والتنزيل في GitHub Actions، ولا يغيّر كود التطبيق أو قاعدة البيانات.


## Iteration 2 — Modular Inventory, FEFO and Purchasing
- إضافة نماذج مستقلة للمستودعات والأرفف والتشغيلات وحركات المخزون والجرد والإعدام والتحويلات والمشتريات والمرتجعات والنواقص.
- إضافة ترقية قاعدة البيانات إلى الإصدار 2، وجداول المستودعات والأرفف وسلسلة التبريد والتشغيلات FEFO ودفتر الحركات والجرد والإعدام والتحويلات والمشتريات والبونص والمرتجعات وسجل تغير الأسعار.
- إضافة مشغلات SQLite لمنع تعديل أو حذف حركات المخزون، وفهرسة التشغيلات حسب الصلاحية، وإنشاء عرض موحد لأرصدة التشغيلات.
- إضافة مستودعات وأرفف ابتدائية وثلاث تشغيلات تجريبية لكل دواء بصلاحيات منتهية وقريبة ومتفاوتة، مع تقسيم الرصيد الافتتاحي الموجود دون زيادة أو إسقاط أي كمية وتسجيله في دفتر الحركات.
- تنفيذ محرك توزيع FEFO حسب أقرب صلاحية، ومنع بيع التشغيلات المنتهية، وتسجيل فتح الباكت تلقائياً، وربط كل بند بيع بالتشغيلات المسحوبة فعلياً.
- ربط الكاشير بخصم التشغيلات الصالحة من المستودعات القابلة للبيع، وإظهار التشغيلة التالية المتوقعة وصلاحيتها في السلة.
- إضافة خدمات فواتير الشراء والبونص وحساب التكلفة الفعلية والمتوسط المرجح وتحديث سجل الأسعار ودفتر المورد.
- إضافة خدمات الجرد واعتماد فروق المخزون بقيود محاسبية، ومحاضر الإعدام، والتحويلات، وتسجيل درجات حرارة الثلاجة.
- إضافة مزود حالة المخزون والمشتريات، وربط الشاشات 11–18 بالتنقل الرئيسي.
- لا يتم دمج فرع الدورة الثانية في main قبل مراجعة نتائج البناء والاختبارات وتجربة التطبيق.

- إضافة قيود SQLite تتحقق من أن الحبات السائبة أقل من وحدات الباكت، وأن إجمالي الحبات يطابق الباكتات المغلقة والحبات السائبة، مع فرض تخزين الأدوية المبردة في مستودع ورف مبردين.


## مراجعة تقوية الدورة الثانية — 2026-11-05
- استكمال نماذج المخزون والمشتريات بخصائص الصلاحية، وتفاصيل التشغيلات، وحركات المخزون، والجرد، والإعدام، والتحويلات، وفواتير الشراء والمرتجعات والنواقص.
- إضافة مشغلات تحقق من اتجاه كميات حركات المخزون، وتطابق التشغيلة مع الصنف والمستودع، وصحة العد الفعلي، وحدود الكميات المرتجعة، مع الإبقاء على دفتر الحركات غير قابل للتعديل أو الحذف.
- رفع إصدار قاعدة البيانات إلى 3 لضمان تطبيق ترقية عمود اكتمال العد على قواعد البيانات الموجودة مسبقاً، دون إعادة إنشاء بيانات المستخدم.
- منع اعتماد جلسة الجرد قبل تسجيل العد لكل التشغيلات، وتحويل الجلسة تلقائياً إلى مرحلة المراجعة بعد اكتمال العد.
- تشديد التحقق من صلاحية التشغيلات ومواقع الأرفف والمستودعات المبردة قبل ترحيل المشتريات، وتحسين حساب المتوسط المرجح عند تكرار الصنف في أكثر من بند.
- تحسين رادار الصلاحية وإدارة الأرفف، وإظهار فروق الاستلام الفعلي للتحويلات، وتجميع أوامر الشراء حسب المورد الأقل تكلفة فعلية.
- توسيع شاشة المشتريات لتشمل خصم الفاتورة والضريبة والمدفوع والمتبقي وقيمة البونص، وتوسيع شاشة الإعدام لدعم عدة تشغيلات مع عرض قيمة الخسارة قبل الاعتماد.
- إضافة مسار استلام أمر الشراء وتحويله إلى فاتورة مشتريات فعلية، مع إدخال رقم التشغيلة والصلاحية وتحديث الكميات المستلمة وحالة الأمر وربط الفاتورة بأمرها الأصلي.
- توسيع اختبارات قاعدة البيانات للتحقق من إنشاء جداول الدورة الثانية، وتوازن أرصدة التشغيلات مع رصيد الصنف، ووجود بيانات الصلاحية التجريبية، ومنع تعديل أو حذف دفتر حركات المخزون، واختبار حالات صلاحية التشغيلة.
