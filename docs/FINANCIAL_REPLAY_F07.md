# F07 — إعادة الإرسال والتعارض والانقطاع والاعتماديات

**الحالة:** IN_PROGRESS، انتظار نجاح CI النهائي.

## تغطية مثبتة مسبقاً دون تكرار

- إعادة تطبيق نفس UUID/hash تعيد `applied=false` دون تغيير الأرصدة.
- نفس UUID مع محتوى مختلف يرفض التعارض.
- فقد الطرف المرجعي يرفض السند كاملاً؛ بعد توفير الاعتماد يمكن إعادة المحاولة.
- خطأ SQLite أثناء إدراج حركة الصندوق يتراجع عن السند والقيد وبنوده وحركة الطرف والصندوق وInbox.
- انقطاع relay يحتفظ بصف Outbox مع `PENDING`؛ إعادة الاتصال تعيد الإرسال.
- ACK غير صحيح لا يغيّر الحالة إلى `SENT`؛ الخادم التجريبي يمنع تكرار UUID.
- رفض النقل دون إعداد trusted relay.

## الإضافة الجديدة

اختبار `F07 lost ACK then retry and duplicate download remain exactly once`: يقبل الخادم التجريبي العملية ثم يعيد ACK تالفاً؛ يظل Outbox معلّقاً. عند إعادة المحاولة مع ACK صحيح لا ينشأ صف relay إضافي، وتطبّق الوجهة العملية مرة واحدة. إعادة استيراد العملية نفسها ترجع `applied=false` مع فحص عدد جميع الأعضاء، الرصيد، Inbox وSQLite FK.

## شروط السلامة

الاختبار يستخدم FakeTrustedFinanceRelay فقط؛ لا يثبت مصادقة الخادم الإنتاجي ولا يفعّل النقل الحقيقي. لا تعديل للسجلات التاريخية أو للعمليات المالية الناجحة.
