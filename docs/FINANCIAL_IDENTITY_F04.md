# F04 — هوية الأعضاء المالية والمراجع المحلية

**النطاق:** حماية UUID والمراجع في سند CASH المزامن، دون تغيير البيانات التاريخية أو تكرار F02/F03.

## تحقق الموجود

- `PostingAndSalesService` يولّد UUIDv4 للمستندات المالية الجديدة.
- `SchemaIteration13` يضيف `cash_transactions.uuid` اختيارياً وفهرساً فريداً للمعرفات غير الفارغة، ويترك التاريخي `NULL`.
- `FinancialVoucherOperation` يرسل UUID لكل عضو، ويعيد بناء `journal_entries.source_id` و`lah_alayh_ledger.doc_id` و`cash_transactions.doc_id` من `voucherId` **المحلي في الوجهة**؛ لا ينقل رقم SQLite من المصدر.
- `financial_operation_inbox` يمنع إعادة التطبيق، و`outbox` يمنع إعادة التقاط نفس العملية.

## الجديد في F04

- حارس صريح قبل أي إدراج في الوجهة يمنع تصادم UUID للقيد أو دفتر الطرف أو الحركة النقدية أو أي سطر قيد، ويرفض بـ`MEMBER_UUID_CONFLICT`.
- اختباران جديدان في **ملف التكامل الموجود**: (1) صف تاريخي بدون UUID يظل كما هو، مع ثبات UUID للحركة الجديدة وتحويل مراجع SQLite إلى سند الوجهة وإعادة الإرسال بلا تكرار؛ (2) UUID حركة موجود مسبقاً يمنع التطبيق دون إدراج سند أو قيد أو Inbox.
- لا يوجد backfill للبيانات التاريخية ولا إعادة ترحيل مستندات قديمة. الهويات التاريخية المجهولة تظل غير قابلة للتصدير حتى مشروع ترحيل موثق مستقل.
