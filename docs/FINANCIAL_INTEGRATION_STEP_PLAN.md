## قواعد إدارة التنفيذ

1. لا يبدأ أي بند دون فحص الكود والعقد والتسليم الحاليين وتحديد ما ينقص فقط. لا يُعاد إنشاء مكونات أو اختبارات قائمة.
2. لكل بند معرف ثابت أدناه؛ الحالة واحدة من `DONE` (مع دليل)، `TODO`، `IN_PROGRESS`، `BLOCKED`. لا يُعلن النجاح اعتماداً على وجود كود فقط.
3. توثَّق في سجل التنفيذ أسفل هذه الوثيقة: الملفات/الالتزام، الاختبارات الجديدة، رابط GitHub Actions على نفس الالتزام، النتائج والفشل والإصلاح، وما لم يثبت.
4. لا تُفتح قوائم سماح البيانات المالية العامة، ولا يُفعل relay الإنتاجي، ولا تُنشر قواعد Firebase أو أسرار أو Claims حتى إتمام حواجز الخصوصية والهوية واعتماد صريح.
5. المبالغ بالدقة المحددة للعملة؛ لا نقل لرقم SQLite المحلي كهوية عامة، ولا تكرار قيد أو حركة أو إعادة ترحيل على المستقبِل. يجب أن ينجح التطبيق الذري والـrollback وإعادة الإرسال.
6. يبدأ العمل على `feature/central-medicine-catalog` دون تعديل `main` ودون ترحيل بيانات تاريخية اعتباطي.
7. تداخل P0-05 (سلامة العقد والتطبيق) مع P0-06 (التقاط المصدر وOutbox والنقل) طبيعي؛ ننفذه مرة واحدة ونوثق اعتماده في المرحلتين.
