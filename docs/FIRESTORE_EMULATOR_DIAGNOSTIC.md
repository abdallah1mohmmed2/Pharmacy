## متابعة CI — فشل الاختبارات وتهيئة PDFium (2026-11-08)

### نتائج التشغيل 42467176990

- Firebase Emulator، اختبار إصدار الهوية، وFlutter Analyze: نجحت.
- Flutter Test: توقف أثناء بناء native assets لحزمة `sqlite3 3.5.2`؛ الملف المنزّل `libsqlite3.x64.linux.so` لم يطابق SHA-256 المضمّن في الحزمة. هذا النمط متوافق مع استبدال تنزيل GitHub Release باستجابة وسيطة/خطأ من الشبكة، ولا يجوز تغيير قيمة hash أو تعطيل التحقق.
- Windows: سكربت PDFium فشل بسبب regex مكتوب بشرطات مائلة مضاعفة، فلم يتعرف على سطر CMake. لم يبدأ بناء Windows.

### المعالجة الجديدة

- اختبار Linux فقط يثبت حزمة النظام `libsqlite3-0` ويضيف مؤقتاً إعداد hook إلى نسخة `pubspec.yaml` في مساحة CI لاستخدام SQLite النظام على Linux؛ تبقى المنصات الأخرى على ملفات sqlite3 الموقعة/المتحقق منها التي توفرها الحزمة. لا يتغير ملف pubspec الملتزم ولا يتم تجاوز فحص سلامة التنزيل.
- تهيئة PDFium أصبحت تسبق محتوى `windows/CMakeLists.txt` مباشرة، بدلاً من الاعتماد على marker أو regex خاص بقالب Flutter.
- لا تغيير على شيفرة التطبيق أو مخطط قاعدة البيانات أو اختبارات الأمان أو قواعد Firestore.

### حالة التحقق

## متابعة CI — تنزيل PDFium موثّق دون الاعتماد على GitHub Releases redirect (2026-11-08)

أثبت سجل التشغيل `42467772457` أن رابط GitHub Releases يعيد HTTP 504 بشكل متكرر على Windows runner، حتى بعد ثلاث محاولات. لذلك أزيل الاعتماد على ExternalProject لتنزيل PDFium أثناء CMake:

- تنزيل أصل Windows من GitHub Release Assets API بالمعرّف `709415678`.
- التحقق من SHA-256 الثابت المطابق لبيانات الأصل المنشورة: `8d48973e3eb472dda0f5f2435e595ac043f9f2219dd71883392f549445afa8a5`.
- استخراج الأرشيف محلياً والتحقق من وجود `PDFiumConfig.cmake`.
- تعديل ملف CMake المؤقت داخل Pub cache في CI فقط ليربط مصدر PDFium المحلي المتحقق منه، مع رفض التعديل إذا تغير قالب plugin المتوقع.
- لا يُعدّل كود التطبيق أو ملف pubspec أو ملفات plugin المحفوظة في المستودع، ولا يتم تجاوز التحقق من سلامة الملف.

التعديل أرسل في commit `dad8be4130cf93fb3f2374e06e5105309e0abde4` على الفرع الحالي. يلزم التحقق من التنزيل والتجزئة واكتمال بناء Windows وAndroid والاختبارات ورفع artifacts في تشغيل جديد.


### تصحيح إعداد SQLite على Linux

أظهر التشغيل `42468103481` أن إصدار `sqlite3 3.5.2` المستخدم فعلياً لا يقبل خريطة المنصات في حقل `source`؛ يقبل قيمة مصدر واحدة فقط. تم تعديل إعداد CI المؤقت إلى `source: system` (داخل وظيفة Linux فقط)، بعد تثبيت `libsqlite3-dev`، مع بقاء إعداد المشروع الدائم دون تغيير. هذا لا يغيّر اختباراً أو يتجاوز فحص hash؛ بل يوجّه اختبار FFI على runner إلى مكتبة النظام المتوفرة.
